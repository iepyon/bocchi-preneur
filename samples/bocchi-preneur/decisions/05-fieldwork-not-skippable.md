# 意思決定ログ：現場の宿題を消さず、「まとめて進めて」でも問い詰めを抜かない

- 日付：2026-11-21
- 工程：2 企画（シミュレーション Round 5 の R5-6・R5-7 の直し方）
- プラグインの版：0.16.0

## 問い

1. 本人が「インタビューは想定で」と言ったとき、AIの想定インタビューを作るか。作るなら、本物の宿題が消えないようにどう記録し、どう外に出るよう促すか（R5-7）。
2. 「まとめて進めて」と言われたとき、どこまで束ねてよいか（R5-6）。

## 選択肢

| 論点 | 選択肢 | 決定 |
| --- | --- | --- |
| 想定インタビュー | 作らない／1回目は断り、2回目は作る（AI案）／練習としてなら初回から作る | 1回目は理由を伝えて断るだけ。2回目に頼まれたら作る |
| 記録先 | state.md の宿題欄／意思決定ログ／Git のコミット／report.md | 4つすべて |
| 外に出る促し方 | 誰に・いつまでを決める（AI案）／毎回思い出させるだけ／期限を過ぎたら強める | 想定を作った直後に、本物に聞く1人目（名前か役職）と期限を本人が決める。期限切れは再開時に表示するだけ |
| 止める場所 | 検証の前（AI案）／工程ゲート（今と同じ）／調査の出口 | ステップ1の本物の宿題がゲートを満たすまで、ステップ5に入れない。ステップ5の本物の宿題が満たされるまで、ステップ7に入れない。社内の新規事業の承認者への聞き取りでは止めない |
| 押し切り | 絶対に入れない（AI案）／意思決定ログを書けば入れる | 絶対に入れない。代わりに「外に出る」か「やめる」を示す |
| 対象の宿題 | 現場の宿題すべて（AI案）／ステップ1だけ | 現場の宿題すべて（課題インタビュー、価値検証、承認者への聞き取り） |
| まとめて進めて | 工程ごとに最低限を決める（AI案）／今回は外す／受け付けない | 公開に近いほど厳しく。調査は選択式だけ束ねる。企画・試作は説明チェック2問とゲートを省かない。検証・公開は受け付けず1問ずつ |
| コミット | AIがコミットする／しない | 想定インタビューの記録はAIがコミットし、メッセージに「宿題：未着手（想定で代用）」と入れる。push はしない |

## 決定

本人の言葉：「インタビューは仮想は一度は断るが作ってもよい。ただし、宿題であることを履歴にも記録し、建物の外に出てを促すように設計したい」。上の表の細部は、AIの確認の問いに本人が選択と「はい」で答えた。

## 根拠と未検証の前提

- 根拠：シミュレーション Round 5 の R5-7（P4：想定を断ったあと、宿題もリハーサルも出ずに検証まで進んだ）と R5-6（P1：試作の受け入れが「まとめて進めて」で触っただけになった）【行動】（シミュレーション上）
- 未検証の前提：
  - ステップ5に入れないことで、離脱が増えすぎない（企画書 H4 の継続率）
  - 期限切れの表示だけで、本人が外に出る

## 見直す条件

- 共同検証で、ステップ5の手前で止まったまま2週間以上動かない受講者が半数を超えた場合
- 想定で代用中の宿題のうち、期限までに本物に聞けたものが3割に満たなかった場合（促し方を強める）

## 影響

- プラグイン：SKILL.md（絶対ルール、ステップの移動、セッション開始時）、`interview-kit.md`、`explain-check.md`、`05-value-test.md`、`07-build.md`、`decision-log.md`、`manager-report.md`、`migrations.md`、state.md の雛形、status
- これは「本人が進むと言えば止めない」の原則の例外になる。SKILL.md に例外として明記する
