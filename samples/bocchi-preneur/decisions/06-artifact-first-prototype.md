# 意思決定ログ：試作は、まずアーティファクトで動くアプリにする。だめなら Web

- 日付：2026-11-22
- 工程：2 企画（プラグインの方針の見直し）
- プラグインの版：0.18.1 → 0.19.0

## 問い

試作（ステップ4）は「アーティファクトか Web か」を同じ重さで並べていた（`04-minimal-tech-decisions.md`）。アーティファクトは、記録を残す、利用者を識別する、AIと話す、同時にいる人とやりとりする、といった機能で、見た目だけでなく実際に動く試作品を作れる。どちらを勧めるか。

## 選択肢（AI案）

| 選択肢 | 良い点 | 懸念 |
| --- | --- | --- |
| A：社内向けだけアーティファクトを勧め、社外向けは Web を勧める | 社外の人が記録を書き込めない制約に正直 | 社外向けで、早く安く試せる機会を逃す |
| B：社外向けも、まずアーティファクトを勧め、だめなら Web | サーバーなしで速く試せる。参加者が Claude を使っていれば社外でも足りる | 社外の人は、メールで編集者として招かないと記録を書き込めない。編集者はページを公開し直せる |
| C：今のまま同じ重さで並べる | 変更がない | 技術名を言われると比較が飛ぶ（Round 5 の R5-13） |

## 決定

B。本人の言葉：「社外もまずはclaude使う環境をすすめて、だめならWEB」

あわせて、画面設計（ステップ3）でアーティファクトの種類「Design」を選択肢に加える。本人の言葉：「オススメで」（AI案：使い捨てHTMLを標準のまま、Design を選択肢に加える）

## 根拠と未検証の前提

- 根拠：本人の判断【推測】。アーティファクトの機能の説明（書き込める人、AIの費用は使う人の利用枠、同時にいる人とのやりとりは残らない）【行動：機能の型定義を読んで確かめた】
- 未検証の前提：
  - 社外の参加者が、Claude を使っていて、編集者として招かれることを受け入れる
  - 試作品の中のAIの許可の画面が、参加者の反応を大きく変えない
  - プラグインを使う環境で、AIがアーティファクトを作れる

## 決めたこと

- 選ぶ前に3つを確かめる：参加者が Claude を使っているか、記録を書き込める立場で招けるか、本物のお金を受け取るか・不特定の人に公開するか
- 機能は、仮説検証で【行動】と【コミット】を記録する役目から選ぶ。原則いつも：記録が残る（db）・誰が使ったか分かる（user）。場面に応じて：AIと話せる（sample）、今いる人とやりとりできる（room）、画面に感想を書き込める（comments）、いつもの道具のデータを使う（mcp）など
- 価値検証では、AIが試作品の記録を直接読んで集計する
- 本番実装では Web に作り直し、試作品の記録を引き継ぐかを本人が決める

## 見直す条件

- シミュレーションまたは実際の利用で、社外の参加者を編集者として招けず、アーティファクトから Web への切り替えが半分以上の案件で起きた場合
- プラグインを使う環境でアーティファクトを作れないことが多い場合
