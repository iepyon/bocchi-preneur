- 第1版の Node.js 版（`app/`）は比較用に残す

### 保存の仕方とアクセスのきまり
| 置き場所 | 中身 | 読める人 | 書ける人 |
|---|---|---|---|
| logs/<利用者ID> | 今日の一手、できた、通過記録、灯した日 | 全員 | 本人（運営者も可） |
| cheers / thanks / bows | 応援・お礼・頭を下げる | 全員 | 使える人 |
| signs | 15分相談（所属はここだけ。相談が終わると消える） | 全員 | 使える人 |
| rooms/<相談ID>（＋msgs） | 会議・共有リンクと文字 | 全員（画面は当事者だけに出す） | 使える人。相談を終えると消える |
| pending/<利用者ID> | 公開前の学び | 本人と運営者 | 本人と運営者 |
| lessons | 公開した学び | 全員 | 運営者だけ |
| outcomes/<利用者ID> | 相談の結果（動き出せた・48時間以内にできた） | 本人と運営者 | 本人と運営者 |
| experts | 招待した経験者の印 | 全員 | 運営者だけ |

**残るリスク（ステップ9で扱う）**：相談部屋の文字とリンクは、画面では当事者にしか出さないが、保存の仕組みの上では、ページを使える人なら技術的に読める。相談が終わると消すので、残る時間は最長でも相談時間＋その後の片付けまで。価値検証は社内の人だけで行い、公開工程で作り直すかを判断する。

## プロトタイプ実装

> 架空のシミュレーション。プラグイン v0.9.0 の `04-prototype.md` に沿って作成。

### 受け入れ条件（本人の言葉）
1. 「スマホのブラウザで開いて、登録なしで今日の一手を灯せる」
2. 「別の人の画面で私の灯にあたると、私の残響に届く」
3. 「サインを出して、別の人が応じたら、2人だけの部屋で話せて、しぐさを送って終われる」

書き置きと痕跡は「価値検証で測るのは灯なので、動けばいい」として受け入れ条件に入れなかった。

### 選んだ技術とその理由

| 案 | 嬉しいこと | 失うこと |
|---|---|---|
| A：依存なしの Node.js ＋ JSONファイル保存 | 追加のインストール不要。`node server.js` だけで動く。中身が全部読める | 利用者が増えると保存が遅くなる。本番では作り直しが要る |
| B：Webフレームワーク＋データベースのサービス | 本番にそのまま近づける | 試作に設定の手間がかかる。アカウント作成が要る |
| C：ノーコードツール | 画面がすぐできる | 「書き置きは定型文だけ」「部屋は時間で消える」などの細かい決まりを作りにくい |

本人の選択：**A**。「3週間で20人に渡すだけ。本番で作り直すのは受け入れる」（`../../decisions/04-prototype-stack.md`）

### 骨格からの反映
- 初回・空・失敗の状態は `03-wireframe.md` の文言どおりに実装した。
- 表層（色や装飾）は作り込まない方針だったが、「暗い中の小さな灯」がコンセプトそのものなので、暗い背景と灯の色だけは入れた。デザインシステムはステップ8で作る。

### 触り方
1. Node.js 18 以上を入れる。
2. `samples/hitoribi/app` で `node server.js` を実行する。
3. ブラウザで `http://localhost:3000` を開く。
4. 2人分を試すときは、もう1つ別のブラウザ（またはシークレットウィンドウ）で同じURLを開く。

### AIが行った確認（2人のユーザーを自動で操作するテスト）

| シナリオ | 結果 |
|---|---|
| Bが灯す → Aがあたる → Bの残響に届く | 通った |
| Bが場所に書き置き（2文つなぎ）と痕跡を残す | 通った |
| 自由な文字を語として送る（定型文の抜け道） | サーバーが拒否した |
| Bがサインを出す → Aが応じる → 部屋で話す → Bが「礼」 → Aの残響に届く | **初回は失敗**。Aが古い一覧を見ていて、別のサインに応じた |
| 残響の一覧を開く | **初回は失敗**。一覧が描けず、文字が崩れた |
| `../` で上の階層のファイルを読む | 拒否した（404） |

失敗した2件の直し方：
- タブを移るたびに最新の状態を読み直すようにした。
- 残響の一覧の組み立て方の誤りを直した。

直した後、全シナリオが通り、画面のエラーは0件だった。
