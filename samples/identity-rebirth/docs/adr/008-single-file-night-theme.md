# ADR-008: 試作品は1つのHTMLに収め、ライブラリを使わず、夜の一色で作る

**状態:** 採用
**日付:** 2026-11-22
**決めた人:** 本人の依頼（「デザインをバー仕立てに」「マスターのキャラアイコン欲しいな」「白のアイコンで。カラー不要です」）を、AIが作りに落とした。単一ファイル・ライブラリなしはAIが決めた
**元の意思決定ログ:** `decisions/06-name.md`
**コミット:** e5a4806、9b36c8a（版5）、1113c5a（版6）、8fdcb54（版11）

## 背景
- 試作品は何度も作り直す（同じ日に版21まで更新した）。表層（見た目）はステップ8の仕事だが、本人の依頼で先取りした
- アーティファクトは外部の読み込み先が限られる（スクリプトは決まったCDN、フォントは Google Fonts だけ）

## 決定
- 1つの `index.html` に、見た目・画面・動きをすべて収める。ライブラリは使わない
- 見た目は夜の酒場の一色で作る（明るい表示には切り替えない）。看板の文字だけを琥珀色に光らせる
- 絵（場のカード、マスターのアイコン）はすべて、ページの中に書いた線画（SVG）にする。マスターは白い線だけ
- 呼び名をバーにそろえる：マスター（AI）、黒板（喪失の地図）、ボトルキープ（自分だけの記録）、今夜のカウンター（いまいる人）、グラスの跡（7日間の跡）
- スマホの幅では「対話」と「黒板」を切り替え、対話の上に地図の進み具合の帯を出す（版21）

## 検討した選択肢

### A: 1つのHTML、ライブラリなし（採用）
**良い点:** 読み込みに失敗しない。どこを直すかがすぐ分かり、作り直しが速い
**懸念:** ファイルが長くなる（試作品の範囲では問題にならない）

### B: React などを使う
**良い点:** 画面が増えたときに整理しやすい
**懸念:** 試作品の画面の数では、得るものより手間が大きい

## 結果
- 楽になること：本人の細かい依頼（場の追加、並び替え、アイコン）を、その場で直して公開できる
- 難しくなること：明るい表示を好む人には暗く感じられる
- 見直すこと：ステップ8（デザイン）で、表層を本人と選び直す。Web 版（ステップ7）では、画面ごとに分けて作り直す
