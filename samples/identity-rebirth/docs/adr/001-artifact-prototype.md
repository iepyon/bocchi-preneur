# ADR-001: 試作品は Claude のアーティファクトで作る

**状態:** 採用
**日付:** 2026-11-22
**決めた人:** 本人（選択式で選んだ）。AIが選択肢を示した
**元の意思決定ログ:** `decisions/03-skip-to-artifact-prototype.md`、`decisions/04-prototype-data-and-ai-role.md`
**コミット:** 6d7d099、e5a4806

## 背景
- 試作品の期限は 2026-12-12。本人が使えるのは週末だけ（週16時間ほど）
- 価値の中心はAIとのひとり対話。試作品の役目は、利用者の【行動】（対話した、物語を残した、「打ち明けた」を押した）を記録に残し、ステップ5の価値検証に回すこと
- 検証に参加するのは、1人目のアジャイルコーチを含む社外の10人ほど。お金は受け取らず、一般公開もしない

## 決定
Claude のアーティファクト（claude.ai 上で動くアプリ）で作る。参加者は Claude を使う少人数の信頼できる人で、メールで編集者として招く。

## 検討した選択肢

### A: アーティファクト（採用）
| 観点 | 評価 |
|---|---|
| 作る手間 | 低い。サーバーが要らない |
| 費用 | AIは使う人自身の Claude の利用枠を使うので、作る人の原価はかからない |
| 参加者の制約 | Claude を使い、編集者として招ける人に限られる |
| 記録 | `db`（記録）、`user`（識別子）、`sample`（AI）、`room`（いまいる人）が使える |

**良い点:** リンクを渡すだけで試せる。記録を Claude が直接読んで集計できる
**懸念:** 一般公開や決済に向かない。編集者はページを公開し直せるので、招く相手を信頼できる人に限る必要がある

### B: Web（自分で動かすサーバー）
| 観点 | 評価 |
|---|---|
| 作る手間 | 高い。サーバー、認証、AIの鍵の管理が要る |
| 費用 | AIの利用料を作る人が払う |
| 参加者の制約 | Claude を使わない人にも試してもらえる |

**良い点:** 誰にでも試してもらえる。本番に近い
**懸念:** 週末3週間では、試作品より土台づくりに時間を取られる

## 比べたうえでの判断
参加者が少人数で Claude を使える前提なら、作る手間と原価の差が大きい。検証で確かめたいのは「ひとり対話のあとに打ち明けるか」で、誰にでも公開できることではない。

## 結果
- 楽になること：サーバーなしで、週末のうちに何度も作り直せる（版1から版21まで同じ日に更新できた）
- 難しくなること：Claude を使わない人は参加できない。継続利用の測り方は、アーティファクトの記録に限られる
- 見直すこと：公開工程（ステップ7）で Web 版に作り直す。そのとき試作品の記録を引き継ぐ
