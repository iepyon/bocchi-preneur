# ADR-004: AIは毎回、場面メモと全対話を送り、JSON で返させる。上限はかけず回数だけ数える

**状態:** 採用
**日付:** 2026-11-22
**決めた人:** AIの利用上限は本人が選んだ（「上限なしで回数だけ数える」）。呼び出し方はAIが決めた
**元の意思決定ログ:** `decisions/04-prototype-data-and-ai-role.md`
**コミット:** e5a4806、1d318ff（版21で場面メモと往復の数を分けた）

## 背景
- アーティファクトの `sample` は記憶を持たない。毎回、指示とデータと出力の形を送る必要がある
- 1回の返事で、マスターの返事と、喪失の地図の更新と、落ち込みのサインの有無を、まとめて受け取りたい
- 対話の中身は保存しない（ADR-002）

## 決定
- 毎回、マスターへの指示＋「場面メモ」（場・そこにいた人・話題）＋「いま（何往復目か）」＋「これまでの対話（相手：／マスター：）」を1つの文字列で送る
- `sample.json` で `{reply, map, concern}` を受け取る。物語は別の呼び出しで `{story, draft, concern}` を受け取る
- `cache: false`（同じ入力でも毎回作り直す）
- 上限はかけない。呼んだ回数を `usage.aiCalls` に数え、ステップ6でAI原価を試算する材料にする
- 許可がない・混んでいる・利用枠を使い切った・応えられない内容、の4つの失敗を、それぞれ別の文面で伝える。失敗したら書いた言葉を入力欄に戻す

## 検討した選択肢

### A: 文章で返させ、地図は別に呼ぶ
**良い点:** 返事が自然になりやすい
**懸念:** 呼び出しが2倍になり、遅く、利用枠も2倍使う

### B: JSON でまとめて返させる（採用）
**良い点:** 1回で返事・地図・サインが揃う
**懸念:** JSON の形が崩れると失敗する。返事の文が硬くなりやすい

## 結果
- 楽になること：対話を保存しなくても、画面の中で全対話を持って送るだけで済む
- 難しくなること：対話が長くなるほど1回の入力が大きくなる（上限なしのため、長い人ほど利用枠を使う）
- 見直すこと：ステップ6で、1人あたりの呼び出し回数から上限を決め直す
