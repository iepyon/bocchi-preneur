# ADR-007: 回数の記録の書き込みを、1件ずつ順番に行う

**状態:** 採用
**日付:** 2026-11-22
**決めた人:** AI（画面の自動操作で見つけた不具合を直した）
**コミット:** d655110

## 背景
- `usage/<識別子>` は、読み出して数を足し、書き戻す形で更新している
- 1回目の送信では、「対話を始めた回数＋場・話題・そこにいた人」と「AIを呼んだ回数」の2つの更新が同時に走る
- 画面の自動操作で、対話の回数が0のまま、場・話題の回数が空のままになることが分かった。後から書いたほうが、前の書き込みを上書きしていた

## 決定
更新を1本の待ち行列にのせ、前の更新が終わってから次を始める。失敗しても、使う人の流れは止めない。

## 検討した選択肢

### A: 1件ずつ順番に行う（採用）
**良い点:** 1人が自分の記録だけを書く形なので、これで足りる。簡単
**懸念:** 同じ人が2つのタブで同時に使うと、まだ上書きが起きうる

### B: 回数ごとに別の記録に分け、追記だけにする
**良い点:** 上書きが起きない
**懸念:** 集計の手間が増える。試作品には重い

## 結果
- 楽になること：撤退基準の集計に使う回数が正しく残る（自動操作で、対話1回・場・話題・そこにいた人がそれぞれ1と残ることを確かめた）
- 見直すこと：Web 版（ステップ7）では、サーバー側で数を足す形にする
