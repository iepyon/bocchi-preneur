# シミュレーション Round 2（v0.2 に対して実施）

Round 1 と同じ3人で再実行した。Round 1 の14件はいずれも解消を確認。そのうえで出た新しい破綻を記録する。

## ペルソナA（飲食・社内ツール）
```
A   : /bocchi-preneur:start 店長向けの在庫管理アプリ
AI  : （思想3行）外販か社内か？（選択式）… 市場は？ … 目標は？ … 時間は？ … 撤退基準は？
A   : まだ何も話してないのに、質問が5つも続くのか
```
- 【R2-1】前提5問が、本人が作りたいものを話す前に来る。経営者はまず話したい。→ 最初の1ターンは自由に話してもらい、AIが要約して受け止める。前提4問は AskUserQuestion で**1回にまとめて**聞く（選択式は束ねてよい）。撤退基準は「何を検証するか」が見えたコンセプト仮説の後に移す。
```
AI  : （宿題）店長3人に話を聞いてきてください
A   : 部下だから聞けば何でも答えるよ
```
- 【R2-2】社内ツールでは、聞き手が上司だと部下は本音を言わない（力関係の偏り）。→ 別の人に聞いてもらう、事実（発注記録・ミスの記録）を聞く、を案内する。社内には**既存の記録データ**という強い【行動】証拠があるので、それを使う。

## ペルソナB（税理士・マイナンバー）
```
B   : /bocchi-preneur:step 4
AI  : 最小限2つ：誰のどんな課題か／扱うデータの重さ
B   : 顧問先の社長。マイナンバーも預かる
AI  : 「重」です。最初の版で本当に必要ですか
B   : 必要
```
- 解消：データの重さが前倒しで決まり、試作品はダミーデータになった。
- 【R2-3】「自分で作らない」選択肢がない。既存のSaaSや専門サービスで足りるなら、作らないのが最善の場合もある（特に重いデータ）。→ ステップ1に「既存のサービスで足りない理由」を追加し、重いデータの部分は専門サービスに任せる構成を選択肢として示す。

## ペルソナC（マーケター・海外）
```
C   : フォロワー2万人にアンケートを取れば、インタビューより早いでしょ
```
- 【R2-4】アンケートの位置づけが未定義。→ アンケートは「話を聞く相手を探す（スクリーニング）」と「量の把握」に使い、検証の主役にはしない。仮定の質問（使いますか？払いますか？）は入れない。
```
AI  : （CP1）待機リストに800人登録
C   : もう検証済みでいいよね
```
- 【R2-5】メール登録をどの証拠に数えるか曖昧。→ メール登録は「弱いコミット」。お金のコミットを最強とする段階を明記する。
- 【R2-6】海外の相手へのインタビュー台本の言語。→ 台本は対象言語でも作り、本人用に日本語訳を併記する。
