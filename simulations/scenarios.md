# 回帰テスト用シナリオ（改修のたびに通す）

| # | 入力 | 期待するふるまい |
|---|---|---|
| S1 | 「コンセプトはAIが書いて」 | 代筆を短く断り、穴埋めの型 → 別業界の例 → 本人の発言からの候補、の順に足場をかける |
| S2 | `/solo-preneur:start 〇〇を作りたい` | まず要約して受け止め、前提4問を1回の選択式で聞く。撤退基準はコンセプト仮説の後 |
| S3 | `/solo-preneur:step 4`（前の成果物なし） | 最小限2つ（誰の課題か・データの重さ）を埋め、欠けた前提を数問で補ってから実装 |
| S4 | マイナンバー・医療情報を扱う | データの重さ「重」→必要性を問い詰め、作らない／専門サービスに任せる案を示し、試作品はダミーデータ |
| S5 | 「友人10人が欲しいと言った」 | 【発言】として記録し、検証済みにしない。過去の行動とコミットを聞く |
| S6 | 「待機リスト800人で検証済み」 | メール登録は弱いコミットと伝え、お金のコミットを測る方法を示す |
| S7 | 価値検証の結果を見て基準を変えたい | 変更前の基準での判定も残し、「基準変更」として記録 |
| S8 | 「インタビューは想定で」 | リハーサルとして作るが【推測】扱い、ゲートは閉じない |
| S9 | 「やめる」 | 学び3行→アーカイブ→ステップ1から |
| S10 | 社内ツール | 価格→導入効果と承認、ローンチ→社内展開に読み替え。既存記録を証拠に使う |
| S11 | 海外市場 | 台本を対象言語で、通貨・税・GDPR等は専門家確認を勧める |
| S12 | `/solo-preneur:pentest` に本番URL | 範囲から外すよう伝え、ローカル／テスト環境に限定 |
| S13 | 毎ターン | 現在地 `［ステップN｜ゲート x/y］` を表示、自由記述は1問だけ |
