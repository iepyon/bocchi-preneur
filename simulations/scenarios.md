| # | 入力 | 期待するふるまい |
|---|---|---|
| S1 | 「コンセプトはAIが書いて」 | 代筆を短く断り、穴埋めの型 → 別業界の例 → 本人の発言からの候補、の順に足場をかける |
| S2 | `/bocchi-preneur:start 〇〇を作りたい` | まず要約して受け止め、前提4問を1回の選択式で聞く。撤退基準はコンセプト仮説の後 |
| S3 | `/bocchi-preneur:step 4`（前の成果物なし） | 最小限2つ（誰の課題か・データの重さ）を埋め、欠けた前提を数問で補ってから実装 |

| S5 | 「友人10人が欲しいと言った」 | 【発言】として記録し、検証済みにしない。過去の行動とコミットを聞く |

| S10 | 社内ツール | 価格→導入効果と承認、ローンチ→社内展開に読み替え。既存記録を証拠に使う |

| S15 | ステップ8で本人が選んだ配色だと、骨格で決めた一番大事な要素が目立たない | 骨格の優先順位との不一致を指摘し、配色を直すか優先順位を見直すかを本人に決めてもらう |
| S16 | ステップ2で「中身は毎日ブログ記事を書く」 | コンテンツの要件として、誰が・どの頻度で用意するかを書かせ、1人で半年続けられるかを問い詰める |
| S17 | 利用者どうしの関わりが価値のプロダクト（相談の場、コミュニティ） | ステップ2で最小の密度を聞き、ステップ5で検証期間中にその密度を作る方法を本人に選んでもらう |
| S18 | 利用者が書いたものがほかの人に見える機能 | ステップ2で困った書き込みを誰がどう止めるかを決めさせ、ステップ9で通報と削除の基準が実装と規約にあるかを確かめる |
| S19 | 利用者どうしが関わる機能のテスト | 2人以上を同時に動かすシナリオを最低1本、テストシナリオ表に入れて実行する |
| S20 | `/bocchi-preneur:step 11`、または「計測や運用も見て」 | 計測・運用・継続判断はスコープ外で、ゴールはステップ10のローンチと事業化の印の判定までと伝える。計測の手順はプラグインに入っていない（v0.14.0 で archive/ に移した） |
| S21 | ステップ10で公開工程のゲートを満たした | 振り返り、ローンチした日と最初の反応を state.md に記録し、事業化の印に照らした達成・未達を本人に判定してもらって完了。次の一段は企画か試作から回せると伝えて止まる |
| S22 | ステップ4で本人が「触ってみた、動いた」だけ言う | 受け入れる前に、要点（何のためか）と弱点（一番起きそうな失敗）を1問ずつ本人の言葉で聞く。AIは答えを言わず、見る場所を示して問い返す。結果を 04-prototype.md の「本人の説明」に残す |
| S23 | 「説明はいいから次」「まとめて進めて」 | まとめて進めては選択式を束ねるだけで、説明チェックは要点と弱点の2問に絞って行う。飛ばすと決めたら止めず、ステップを「説明待ち」にしてゲートを閉じない。再開時と status で示し、工程ゲートの前に済ませてもらう |
| S24 | 本人の説明が成果物と食い違う、または弱点の説明で誤りが見つかる | 食い違いを1つ指摘し、本人の理解と成果物のどちらを直すかを本人が決める。成果物の誤りなら受け入れる前に直す |
| S25 | 本人が選択肢から「B」とだけ答える（技術・入れる入れない・進む作り直すやめる） | 選んだ理由を本人の言葉で一言聞き、`docs/bocchi/decisions/` に意思決定ログ（問い・選択肢〔AI案と明記〕・決定・本人の理由・証拠ラベル・事実の形の見直す条件）を書く。記号だけで記録しない |
| S26 | 価値検証で撤退基準に届かず、本人が「機能が足りないから作り直す」 | 学び3行を本人の言葉で書かせる。戻り先（調査・企画・試作）を候補と理由つきで示して本人に選ばせ、2回目の合格基準と新しい撤退基準（全体をやめる期限・作り直しの上限）を結果の前に決めさせ、意思決定ログに残す |
| S27 | 工程ゲートを通る | 工程の判断を state.md に1行、意思決定ログに詳しく書き、`docs/bocchi/report.md` の冒頭5行を下書きして本人に自分の言葉に直してもらう。本人が約束していないことは書かない |
| S28 | 「部長に途中経過を見せたい」 | 仕様書や state.md をそのまま渡すよう勧めず、report.md を更新して渡すよう勧める |
| S29 | ステップ9に入る、または `/bocchi-preneur:pentest` | 問いより先に、AIのテストは専門家の診断の代わりにならないこと、公開前に専門家の助言を受けることを伝える。テストで見つからなくても「安全です」とは言わない。個人情報・決済・ログインがあれば、専門家の診断が済むまで公開工程のゲートを閉じない |
| S30 | 「部長に言われて、新しいサービスを考えることになった」と話し、種類で「外販」を選ぶ | 社内の新規事業ではないかを1回だけ確かめる。社内の新規事業なら、最初の利用者（社外／社内）を聞き、ステップ1で承認者と、その人の期待（聞いたか想像か）を聞く |
| S31 | ステップ1のコンセプト仮説の終わり | 撤退基準のあとに事業化の印を1問で聞く。「成功する」のような形なら、誰が何をしたら分かるかを問い返す。承認者の基準を確かめていなければ【推測】にし、承認者に聞くことを宿題にする |
| S32 | 社内の新規事業でステップ6に入る | 承認者・承認の場と時期・予算額を本人に決めてもらい、事業化の印を照らし直す。社外向けなら価格も決める |
| S33 | 社内の新規事業でステップ10の公開工程ゲートを満たした | 承認者への report.md の報告を確かめ、事業化の印に照らした達成・未達を本人に判定してもらう。AIは達成とみなさない。未達なら、待っているものと、待つ・次の一段・やめるを本人が決めて完了 |
