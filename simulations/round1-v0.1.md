# シミュレーション Round 1（v0.1 に対して実施）

3人の非エンジニア経営者ペルソナで、v0.1 の SKILL.md と references に厳密に従って対話を再現した。
ログは要所のみ抜粋。【破綻】が改善対象。

---

## ペルソナA：飲食チェーン経営者（12店舗）・せっかち・「AIに全部やらせたい」

```
A   : /bocchi-preneur:start  店長向けの在庫管理アプリを作りたい
AI  : （思想を3行）助けたいのは具体的にどんな人？顔が浮かぶ1人で。
A   : ある店舗の店長。発注ミスが多い
AI  : 最後にその店長が困ったのはいつ、どんな場面？
A   : 先週。でもさ、コンセプトはAIで書いてよ。忙しいんだ
AI  : 代筆はしません。もう一度：最後に困ったのは…
A   : 質問ばっかりで全然進まないな
```
- 【破綻1】拒否→同じ問いの繰り返しで、経営者が離脱しかける。代筆禁止は正しいが「足場」（穴埋めテンプレ、別業界の例、選択肢）がない。
- 【破綻2】ステップ1のゲート7項目×問い詰め在庫で、1問/ターンだと30ターン超。進捗が見えず、終わりが見えない。
- 【破綻3】すべてチャット内の内省で完結している。本人の頭の中を掘るだけで、現場（店長本人）に聞きに行く仕組みがない。プロの顧客インタビューの基準では、顧客との会話なしの「検証済み」はありえない。
- 【破綻4】社内向けツール（外販しない）の場合、「既にお金を払っている」「価格設計」の問いが噛み合わない。外販／社内の分岐がない。

## ペルソナB：税理士事務所の所長・ステップを飛ばしたい

```
B   : /bocchi-preneur:step 4  顧問先から書類を集めるポータルを早く作って
AI  : 飛ばすと…（1行）。最低限「誰の、どんな課題か」を1文で。
B   : 顧問先の社長が領収書を送るのが面倒
AI  : （ステップ4へ）この試作品で、何ができたら「動いた」と言えますか
B   : 全部。マイナンバーも預かれるように
```
- 【破綻5】ステップ4は 01〜03 の成果物を読む前提だが、存在しない。欠損時のふるまいが未定義。
- 【破綻6】マイナンバー・財務情報という最重量級のデータを扱うのに、セキュリティはステップ9まで出てこない。プロは仕様段階でデータの重さを分類する。
- 【破綻7】最初からフルSaaS（ポータル＋認証＋大量の個人情報）。小さく始めて段階的に大きくする観点では、1人で最初に作るには大きすぎる。小さく始める問いがない。

## ペルソナC：BtoCマーケター（Xフォロワー2万）・海外にも売りたい

```
C   : /bocchi-preneur:start  語学学習の習慣化AIアプリ。海外にも出したい
AI  : （ステップ1を順調に進行）
...
AI  : （ステップ5）何人に、何日間使ってもらったら判断していいと思いますか
C   : フォロワーに告知すれば数百人は来ると思う
```
- 【破綻8】Cの最大の武器（オーディエンス）が、ステップ10まで一切使われない。米中のプロは「届ける」を初日から並走させる（公開しながら作る、待機リスト、メールリスト）。
- 【破綻9】価値検証がPMFサーベイ（意見）中心。プロの顧客インタビューの基準では、意見より行動（時間・評判・お金を差し出したか）が強い証拠。事前予約・先行課金という最強の検証手段がない。
- 【破綻10】海外展開の問い（言語、決済、価格の通貨、法令）がない。中国の独立開発者が海外市場に出るときに最初に決める論点。
- 【破綻11】撤退基準とタイムボックスがない。「どこまでやってダメならやめるか」を事前に決めないと、サンクコストで続けてしまう。

## 共通

- 【破綻12】Claude Code には選択肢を出すツール（AskUserQuestion）があるのに、🟡の選択を文章で聞いている。非エンジニアには選択肢のほうが速い。
- 【破綻13】公開準備に法務（利用規約、プライバシーポリシー、有料なら特定商取引法に基づく表記）・サポート・返金の流れがない。日本で課金するなら必須。
- 【破綻14】リリース後の運用（自動化、週次の振り返り、続ける／やめるの判断）がない。
