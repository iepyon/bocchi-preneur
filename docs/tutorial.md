# はじめてのぼっちプレナー：使い方チュートリアル

このページは、ぼっちプレナー（bocchi-preneur）をはじめて使う人のための手引きです。インストールから、最初のステップを1回通すところまでを、順に説明します。プログラミングの経験はなくてかまいません。

- かかる時間：準備に15分、最初のステップに15分ほど（そのあとは自分のペースで進めます）
- 対象のプラグインの版：v0.19.0
- 詳しい決まりや変更履歴は [プラグインの README](../plugins/bocchi-preneur/README.md) にあります

> [!NOTE]
> **まだ作っている途中の段階です（v0.x）。** 手順や中身は、これからも変わります。画面の表示やAIの言い回しが、このページと少し違うことがあります。

## 1. このプラグインでできること

社内でプロダクトや新規事業を任された人（PM候補・事業責任者の候補）や、非エンジニアの経営者が、AIと一緒にプロダクトを **課題検証から新規事業化（事業として認められるところ）まで** 進めるのを手伝います。外販、社内の新規事業、社内ツールのどれでも使えます。

合言葉は **「決めるのは人、作るのはAI、確かめるのは現場」** です。

| 誰が | 何をするか |
|---|---|
| あなた | 誰のどの課題を解くか、価値があるか、いくらで売るか、続けるかやめるか、を **自分の言葉で** 決める |
| AI | 質問で考えを引き出す。試作品・本番のコード・テスト・レビュー・資料づくりを引き受ける |
| 現場（顧客） | あなたが聞きに行き、本当に困っているか、お金や時間を出すかを確かめる |

ふつうの「AIに作ってもらう」ツールと違うのは、次の3点です。最初は戸惑うかもしれませんが、これがこのプラグインの価値です。

- **AIは事業の答えを代わりに書きません。** 1問ずつ問い詰めて、あなたの言葉で決めてもらいます。
- **AIが作ったものは、あなたが説明できてから受け入れます。** 「動いた」「よさそう」だけでは先へ進みません（説明チェック）。
- **チャットだけでは分からないことは、現場の宿題になります。** 顧客に話を聞きに行くのはあなたです。

## 2. 始める前に用意するもの

| もの | 説明 |
|---|---|
| Claude Code | Anthropic の AI と一緒に作業する道具です。ターミナル版、デスクトップアプリ、VS Code などの拡張機能のどれでも使えます。入れ方は [Claude Code の公式ドキュメント](https://code.claude.com/docs) を見てください |
| 作りたいもののアイデア | ぼんやりでかまいません。「◯◯の人が困っていそう」くらいで十分です |
| 週に数時間 | 1回の作業は15分で区切れるようになっています |
| 話を聞ける相手（あとで） | ステップ1の途中で、対象の人に5人ほど話を聞きに行きます。今いなくても、AIが探し方を手伝います |

Git（変更の履歴を残す仕組み）や Node.js などは、必要になったときにAIが確かめて、入れ方を案内します。先に用意しなくてかまいません。

## 3. インストールする

Claude Code を開き、入力欄に次の2行を **1行ずつ** 貼り付けて送ります。

```
/plugin marketplace add iepyon/bocchi-preneur
```

```
/plugin install bocchi-preneur@bocchi-preneur
```

確認が出たら許可してください。入れ終わったら、Claude Code をいったん閉じて開き直すと確実です。

**入ったかを確かめる**：入力欄に `/bocchi` と打つと、`/bocchi-preneur:start` などの候補が出てきます。出てくれば成功です。

> [!TIP]
> 以前の名前（solo-preneur）で入れていた人は、更新では新しい版になりません。[入れ直しの手順](../plugins/bocchi-preneur/README.md#旧い名前solo-preneurから移る) に従ってください。

## 4. プロダクト専用のフォルダを作る

ぼっちプレナーは **1プロダクトに1フォルダ** で使います。このフォルダがAIの仕事場になり、記録や試作品はすべてここに残ります。

1. 空のフォルダを1つ作ります（例：`ホーム/bocchi/請求書チェック`）。
2. そのフォルダで Claude Code を開きます。
   - ターミナル版なら、そのフォルダに移動して `claude` と入力します。
   - デスクトップアプリや VS Code なら、そのフォルダを開きます。

> [!IMPORTANT]
> ホームフォルダやデスクトップ、ほかの仕事のフォルダで始めないでください。AIが作業を始めずに、専用のフォルダを作るよう案内します。

## 5. 最初の15分：始めてみる

ここからは、架空の例「経理担当の請求書チェックを楽にしたい」で、最初の流れを見ていきます。

### 5-1. 始めるコマンドを入れる

入力欄に `/bocchi-preneur:start` と、作りたいものを続けて書きます。

```
/bocchi-preneur:start 経理の人が毎月やっている請求書の目視チェックを楽にしたい
```

### 5-2. 作業場所の準備（AIがやります）

最初の1回だけ、AIが次のことを確かめ、足りなければ代わりに行います。あなたは表示された確認を許可するだけです。

- 変更の履歴を残す仕組み（Git）を入れる。秘密の情報（`.env` など）は履歴に入らないようにする
- 記録の置き場所 `docs/bocchi/` と、進み具合を書く `docs/bocchi/state.md` を作る

GitHub などに勝手に上げることはありません。

### 5-3. 作りたいものを自由に話す

AIが考え方を短く伝えたあと、作りたいものを自由に話すよう促します。うまくまとまっていなくてかまいません。AIが2〜3行で要約して「この理解で合っていますか」と確かめます。

### 5-4. 3つの前提を選ぶ

続けて、選択肢で3つ聞かれます。ここで選んだものによって、以降の問いが変わります。

| 聞かれること | 選択肢 |
|---|---|
| 種類 | 外販（自分の事業。顧客が払う）／社内の新規事業（社内の承認者が予算を出す）／社内ツール（自社の業務改善） |
| 市場 | 日本／海外／両方 |
| 時間 | 週に使える時間の目安 |

「社内の新規事業」を選ぶと、最初の利用者が社外か社内かも聞かれます。上司から任された案件で「外販」を選ぶと、「社内の新規事業ではありませんか」と1回だけ確かめられます。どれを選ぶかは、あなたが決めます。

### 5-5. 最初の問いに答える

いよいよステップ1（コンセプトと課題検証）です。画面の冒頭には、いまどこにいるかが1行で出ます。

```
［工程1 調査｜ステップ1 コンセプト｜ゲート 0/10］
このプロダクトで助けたいのは、具体的にどんな人ですか。顔が浮かぶ1人で答えてください。
```

- **工程・ステップ**：全体のどこにいるか
- **ゲート**：このステップを終えるための条件のうち、いくつ満たしたか

あとは、問いに1つずつ答えていくだけです。たとえば「経理の人」と答えると、「その中のどんな人ですか」と絞り込まれます。「従業員30人ほどの会社で、経理を1人で担当している人」のように具体的になるまで、問いが続きます。

> [!TIP]
> 15分たったら、区切りのいいところでAIが「今日はここまでで保存できます」と伝えます。そこでやめて大丈夫です。

## 6. AIとのやりとりのコツ

### 問いは1つずつ来ます

自由に答える問いは、1回に1つだけです。選ぶ問いは、選択肢でまとめて出ることがあります。

### 答えに詰まったら、そう言ってください

「分からない」「思いつかない」と書けば、AIが次の順で手伝います。

1. 穴埋めの型を出す（例：「＿＿な人が、＿＿のときに、＿＿で困っている」）
2. 別の業界の例を1つ見せる
3. あなたがこれまでに言ったことから候補を2〜3個並べ、選ぶか書き換えてもらう

それでも出なければ、「答えは現場にある」というサインです。顧客に聞きに行く宿題になります。

### 厳しく聞かれても、責められているわけではありません

AIが問い詰めるのは、あなたの **答え** です。あなた自身ではありません。弱いと分かったうえで「このまま進む」と言えば、そう記録して先へ進みます。

### 記録に付くラベルの意味

記録には、証拠の強さを表すラベルが付きます。下に行くほど強い証拠です。

| ラベル | 意味 | 例 |
|---|---|---|
| 【推測】 | あなたがそう思っている | 「経理の人は毎月困っているはず」 |
| 【発言】 | 顧客がそう言った | 「あったら使いたい」 |
| 【行動】 | 顧客が実際にやった・やっている | 「毎月2日かけて目で照合している」 |
| 【コミット】 | 顧客が時間・評判・お金を出した | 面談に来た、知人を紹介した、事前予約した |

「いいね」「欲しい」は【発言】で、弱い証拠として扱います。【行動】や【コミット】を集めるのが、検証の中心です。

### 図の見方：🔴🟡🟢

ステップごとに、誰が決めるかが違います。

- 🔴 あなたの言葉でしか埋めない（AIは問いを出し、記録し、矛盾を突く）
- 🟡 AIが案を複数出し、あなたが選ぶ。選んだ理由を一言もらう
- 🟢 AIが作る。作る前にあなたが「何ができたら合格か」を決め、できたら確かめて、自分の言葉で説明する

### 説明チェック

AIが作ったもの（仕様の下書き、画面の骨格、試作品など）を受け入れる前に、次の2つを聞かれます。

> 受け入れる前に、あなたの言葉で2つ教えてください。これは何のためのものですか。これで一番起きそうな失敗は何ですか。

AIの書いた文を写すのではなく、自分の言葉で言い換えてください。詰まったら、AIが「どこを見ればよいか」を示します。上司や顧客に聞かれて答えられるようにするための練習です。

## 7. 現場の宿題をこなす

ステップ1の後半（課題検証）と、ステップ5（価値検証）では、実際に人に話を聞きに行きます。これを「現場の宿題」と呼びます。

### 7-1. 台本を作ってもらう

```
/bocchi-preneur:homework
```

AIが、10分で終わる質問の台本と記録シートを `docs/bocchi/fieldwork/` に作ります。誰に何人聞くかを1問だけ確かめられます。目安は、対象に当てはまる人に **5人以上**（社内ツールなら実際の利用者 **3人以上**）です。

### 7-2. 聞きに行く

台本は次のような問いでできています。

- 「最後に＿＿で困ったのはいつですか。そのとき何が起きましたか」
- 「そのとき、どうやって対処しましたか」
- 「それに、どれくらいの時間やお金を使っていますか」

聞くときのポイントは3つです。

1. 自分のアイデアではなく、相手の仕事や生活について話す
2. 「使いますか？」のような将来の話ではなく、過去の具体的な出来事を聞く
3. 話すより聞く

「このアイデアどう思いますか」「いくらなら払いますか」は聞かないでください。相手は気をつかって、本当のことを言いにくくなります。相手の言葉はそのままメモし、録音する場合は必ず相手の了解を取ってください。

### 7-3. 結果を報告する

メモをそのまま貼り付けて送ります。

```
/bocchi-preneur:homework 経理担当Aさん：先月は請求書120枚を2日かけて目で照合。去年、振込先の間違いを1件見逃して…
```

AIが記録シートに整理し、ラベル（【発言】【行動】など）を付けた案を出します。ラベルが合っているか確かめてください。そのあと「聞いてみて、予想と違ったことは何ですか」と聞かれます。

### 「AIに顧客役をやってもらえばいいのでは？」

1回目は断られます。AIが演じる顧客は、あなたの頭の中の顧客なので、予想と違うことを言ってくれないからです。どうしてもと2回目に頼めば作ってくれますが、その場合も宿題は「未着手（想定で代用中）」として残り、本物に聞く1人目と期限を決めることになります。

また、本物の宿題が済むまでは、ステップ5（価値検証）とステップ7（本番実装）には進めません。これは「本人が進むと言えば止めない」このプラグインで、唯一の例外です。

## 8. 中断と再開

- **中断**：いつでもやめてかまいません。Claude Code を閉じるだけです。進み具合は `docs/bocchi/state.md` に残ります。
- **再開**：同じフォルダで Claude Code を開き、`/bocchi-preneur:start` と入力します。AIが次のことを1行ずつ伝えてから再開します。
  - いまどこにいるか、まだ満たしていない条件
  - 出したまま報告していない宿題（あれば、まず結果を聞かれます）
  - 説明チェックがまだのもの
- **様子だけ見たい**：`/bocchi-preneur:status` で、進み具合・出している宿題・これまでの判断・撤退基準などを一覧できます。問いは出ません。

## 9. 次のステップへ進む

ステップの条件（ゲート）を満たしたら、次に進みます。

```
/bocchi-preneur:next
```

- 満たしていない条件があれば、そのうち1つと、埋めるための問いが1つ出ます。
- 全部満たしていれば、成果物を `docs/bocchi/` に書き出し、次のステップの最初の問いが出ます。
- 工程の終わりでは「工程ゲート」を確かめ、その工程で決めたことを1〜2行で振り返ります。あわせて、読み手（上司や承認者など）が5分で読める要約 `docs/bocchi/report.md` が更新されます。

**特定のステップに飛びたい**ときは `/bocchi-preneur:step 3` のように番号を指定します。前のステップが終わっていなければ、飛ばすと何が起きやすいかを1行で伝えたうえで、あなたが決めれば移動します。ただし「誰の、どんな課題か」の1文と「扱うデータの重さ（個人情報やお金を扱うか）」だけは、先に埋めることになります。

### やめると決めてもいい

どのステップでも「やめる」と言えます。やめることは失敗ではありません。学びを3行（分かったこと・次に持ち越すもの・持ち越さないもの）にまとめ、記録を `docs/bocchi-archive/` に移して、新しいアイデアでやり直せます。

## 10. 全体の流れ（5工程・10ステップ）

| 工程 | ステップ | 工程を出るときにあなたが決めること |
|---|---|---|
| 1 調査 | 1. コンセプトと課題検証 🔴＋宿題 | 誰のどの課題か。顧客の行動で確かめられたか |
| 2 企画 | 2. 仕様設計 🔴/🟡 | 入れるもの・入れないもの、扱うデータの重さ、AI利用の上限 |
| 3 試作 | 3. 画面設計 🟡／4. プロトタイプ実装（まず Claude のアーティファクトで動くアプリに。だめなら Web）🟢 | 何を作れば仮説を確かめられるか |
| 4 検証 | 5. 価値検証 🔴＋宿題／6. 価格設計 🔴 | 進む・作り直す・やめる。いくらで売るか |
| 5 公開 | 7. 本番実装 🟢／8. デザイン 🟡／9. セキュリティと公開準備 🟢/🔴／10. ローンチ 🟡 | 公開してよいか。残ったリスクを受け入れるか |

**ステップ1で決める大事なこと2つ**

- **撤退基準**：どうなったらやめるか（例：「◯月◯日までに、◯人中◯人が◯◯しなければやめる」）。先に決めないと、作った分だけ惜しくなってやめられなくなります。
- **事業化の印**：何をもって「事業として認められた」とするか（例：外販なら最初の有料の顧客が◯人つく、社内の新規事業なら承認者が予算をつける、社内ツールなら正式導入が承認される）。最後のゴールで、達成したかどうかをあなたが判定します。

**ゴール**：ローンチまで進み、事業化の印に照らした判定を記録したら完了です。公開後の計測・運用は、いまの版では扱っていません。

> [!WARNING]
> **セキュリティは、AIの点検だけで済ませないでください。** `/bocchi-preneur:review` と `/bocchi-preneur:pentest` はAIによる最低限の自己点検で、専門家の診断の代わりにはなりません。個人情報・決済・ログイン・健康情報を扱うなら、公開前に専門家の診断を受けてください。法務や税についても、AIは下書きと論点の整理まではしますが、法的な助言はしません。

## 11. できたものはどこにあるか

すべて、プロダクトのフォルダの中に残ります。

```
<プロダクトのフォルダ>/
├── docs/bocchi/
│   ├── state.md          進み具合・出している宿題・判断の一覧
│   ├── report.md         読み手（上司・承認者など）への5分で読める要約
│   ├── decisions/        意思決定ログ（あなたが引き受けた判断を1件ずつ）
│   ├── 01-concept.md …   各ステップの成果物
│   ├── fieldwork/        宿題（インタビュー）の台本と記録
│   ├── compare/          見比べ用の使い捨てHTML
│   └── proposal.md       企画書（/bocchi-preneur:proposal を使ったときだけ）
└── （ステップ4以降）プロダクト本体のコード
```

- 上司に進み具合を伝えたいときは `report.md` をそのまま渡せます。
- 本人以外の人が通して読める企画書がほしいときは `/bocchi-preneur:proposal 承認者` のように読み手を指定して書き出せます。まだ決めていないところは「（未決定）」として論点が並びます。企画書を作っても工程は進みません。

## 12. コマンドの早見表

入力欄で `/` を打つと呼び出せます。AIが勝手に呼ぶことはありません。

| 呼び出し | いつ使うか |
|---|---|
| `/bocchi-preneur:start [作りたいもの]` | 始めるとき、再開するとき |
| `/bocchi-preneur:status` | 進み具合を見たいとき（問いは出ない） |
| `/bocchi-preneur:next` | ゲートを確かめて次へ進みたいとき |
| `/bocchi-preneur:step <番号>` | 特定のステップ（1〜10）へ移りたいとき |
| `/bocchi-preneur:homework [メモ]` | 宿題の台本を作る／結果のメモを報告する |
| `/bocchi-preneur:proposal [読み手]` | 企画書を書き出したいとき |
| `/bocchi-preneur:review` | 作ったコードを厳しめに見てほしいとき |
| `/bocchi-preneur:pentest` | 公開前に、自分のアプリへの攻撃テストをしたいとき（専門家の診断の代わりにはならない） |
| `/bocchi-preneur:rca <症状>` | 直らないバグの原因を調べたいとき（AIは原因と案を示すだけで、直さない） |

コマンドを使わずに、ふつうに話しかけても進められます（例：「続きをやりたい」「今日はここまで」）。

## 13. 困ったとき（よくある質問）

**Q. `/bocchi-preneur:start` が候補に出ません。**
A. Claude Code を開き直してください。それでも出なければ、[3. インストールする](#3-インストールする) の2行をもう一度入力してください。

**Q. エラーが出ました。**
A. 画面のメッセージを、そのままコピーしてAIに貼り付けてください。AIが推測で答えずに、メッセージから原因を確かめます。

**Q. 質問ばかりで、なかなか作ってくれません。**
A. 意図どおりです。最初の工程（調査）では、作る前に「誰のどの課題か」を確かめます。作るのはステップ4（プロトタイプ）からです。ステップ4では、まず Claude のアーティファクト（claude.ai 上で動くアプリ）で、AIと話せる・使った記録が残る、といった実際に動く試作品を作ることを勧めます。試してもらう人が Claude を使えないときなどは Web で作ります。作れる感覚を先につかみたいときは、「普段ちょっと困っていることで練習を1つ作りたい」と頼めば、記録に残らない小さな練習ができます。

**Q. 「まとめて進めて」と言ってもいいですか。**
A. 言えます。ただし、まとめられる範囲は公開に近いほど狭くなります。調査の工程では選ぶ問いだけ、企画・試作の工程でも説明チェックは省かれません。検証・公開の工程では受け付けられず、1問ずつ進みます。外れると利用者や承認者に直接響く判断だからです。

**Q. 説明チェックを飛ばしたいです。**
A. 「説明はいいから次」と言えば止められません。そのステップは「説明待ち」として残り、工程の区切りの前に必ず済ませることになります。

**Q. 話を聞ける相手がいません。**
A. AIに相談してください。対象者が集まる場所（業界団体、コミュニティ、SNS など）での頼み方を一緒に考えます。友人・家族・同僚だけになる場合は、そう記録されます。

**Q. 別のプロダクトも並行して進めたいです。**
A. プロダクトごとに別のフォルダを作り、それぞれで `/bocchi-preneur:start` してください。

**Q. プラグインを新しい版にしたいです。**
A. 次の2行を順に入力します。

```
/plugin marketplace update bocchi-preneur
```

```
/plugin update bocchi-preneur@bocchi-preneur
```

古い版で進めていた記録は、再開時にAIが確かめてから新しい形に付け替えます。
