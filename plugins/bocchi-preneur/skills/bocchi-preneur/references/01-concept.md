# ステップ1 コンセプトと課題検証 🔴＋現場の宿題

## 前提
なし（ここが起点）。

## 0. 受け止めと前提の確定
1. まず本人に作りたいものを自由に話してもらい、AIが2〜3行で要約して「この理解で合っていますか」と確かめる。
2. 次の3つを AskUserQuestion で1回にまとめて聞く（選択式）。社内の新規事業を選んだら、最初の利用者を続けて1問聞く。
   - 種類：外販（自分の事業。顧客が払う）／社内の新規事業（社内の承認者が予算を出す）／社内ツール（自社の業務改善）
   - 市場：日本／海外／両方
   - 使える時間：週あたりの時間の目安（試作品までのタイムボックスは、次に自由記述で聞く）
   - （続けて、社内の新規事業のときだけ）最初の利用者：社外の顧客／社内の人
   上司・事業責任者から任された案件、または会社の予算で進める案件なのに「外販」を選んだら、「社内の新規事業」ではないかを1回だけ確かめる。社外向け・社内向けの呼び方は SKILL.md「開始時の分岐」のとおり。
撤退基準と事業化の印は、コンセプト仮説ができてから聞く（下の「撤退基準と事業化の印」）。

## 1. コンセプト仮説（チャット内）

### ゲート（前半）
- [ ] 対象ユーザーが1種類に絞られている
- [ ] 課題が具体的な場面で語られている
- [ ] 社外向けなら「既存のAIツールでは絶妙に不便」な理由を言える／社内向けなら「今のやり方のどこが痛いか」を言える
- [ ] 社外向けなら、その課題に今お金か時間を払っている心当たりを言える／社内向けなら、その課題で失っている時間やミスのコストを言える
- [ ] 社内の新規事業なら、承認者（予算を出す人。役職でよい）と、その人がこの案件に期待していること（本人が聞いた言葉、または【推測】）を言える
- [ ] 機能が「絶対に要る」と「あったら嬉しい」に分かれている
- [ ] **1人で作り切れる大きさか**を確かめた（下記「大きさの問い」）
- [ ] 既存のサービス（SaaSや専門サービス）で足りない理由を言える
- [ ] 撤退基準とタイムボックスが本人の言葉で決まっている
- [ ] 事業化の印（何をもって事業として認められたとするか）が、本人の言葉で、観察できる事実の形で決まっている

### 冒頭の問い
「このプロダクトで助けたいのは、具体的にどんな人ですか。顔が浮かぶ1人で答えてください。」

### 問い詰め在庫（1ターン1つ）
- **対象の絞り込み**：広い答えには「その中のどんな人？」と返す。2種類以上なら1つ選ばせる。ほかの種類は別プロダクトとして記録する。
- **場面の具体化**：「最後にその人がそれで困ったのはいつ、どんな場面でしたか」
- **AIツールとの比較（社外向け）**：「その人が今日ChatGPTを使ったら、どこまで解決しますか。何が足りませんか」
- **財布が開いているか（社外向け）**：「その人は今、この課題に何で対処していますか。お金や時間をいくら使っていますか」。すでにお金で解決している行動（外注、秘書、ツール代、パーソナルトレーナーなど）を探す。なければ「便利だけど払わない」領域の可能性を伝える。
- **AI原価の意識（社外向け）**：裏でAIが動くサービスは、使われるほど原価がかかる。完全無料は難しい。払う意思はステップ5で行動として確かめる、と予告する。
- **大きさの問い**：「最初の版を、1つの機能だけにするとしたらどれですか」。最初から大きなシステム（多機能、多種類のユーザー、大量の個人情報）を作ろうとしていたら、小さく始めて段階的に大きくする進め方を紹介し、最初の一段を本人に決めてもらう。
- **作らない選択肢**：「同じ課題を解く既存のサービスはありますか。それで足りない理由は何ですか」。足りるなら、作らないことも立派な判断だと伝える。重いデータ（マイナンバー、医療情報など）を扱う部分は、専門のサービスに任せて自分では持たない構成を選択肢として示す。
- **機能の仕分け**：「この機能がなかったら、その人は使いませんか？」
- **作る理由**：「数週間かかります。途中で飽きない理由は何ですか」
- **承認者の期待（社内の新規事業）**：「承認者は、この案件で何が分かれば予算を出しますか。本人から聞いた言葉ですか、あなたの想像ですか」。想像なら【推測】と記録し、承認者に直接聞くことを宿題の1つにしてよい。

### 撤退基準と事業化の印（コンセプト仮説の最後に聞く）
やめる条件と、事業として認められたとする条件を対にして決める。1ターン1問で、撤退基準から聞く。

撤退基準：「どうなったら、このアイデアをやめるか別のアイデアに切り替えますか。期限と条件で教えてください。」
形だけ示してよい：「◯月◯日までに、◯人中◯人が◯◯しなければやめる」。数字は本人が決める。
撤退基準を先に決めないと、作った分だけ惜しくなり、やめられなくなる。

事業化の印：「どうなったら、このプロダクトが事業として認められたと言えますか。誰が何をしたら、で教えてください。」
- 例は種類ごとに1つだけ示してよい（外販：最初の有料の顧客が◯人つく／社内の新規事業：承認者が◯円の予算をつける、事業計画が承認される／社内ツール：正式導入が承認される）。数字と条件は本人が決める。
- 「みんなに喜ばれる」「成功する」のような観察できない形なら、誰が何をしたら分かるかを問い返す。
- 社内の新規事業で、承認者の判断の基準を本人が知らなければ、【推測】のまま決めてよい。承認者に確かめることを宿題にする。
- 決めた印は、ステップ6で照らし直し、ゴールで達成・未達を本人が判定する（SKILL.md「ゴール」）。意思決定ログに残す。

## 2. 課題検証（現場の宿題）— 社外向け・社内向けとも必須

チャット内のコンセプトはすべて【推測】。ここで顧客本人に聞きに行く。
インタビューの型に従って、AIが質問台本と記録シートを作り、本人に宿題として出す。

- 社内向けの場合：既存の記録（発注記録、ミスの記録、問い合わせ履歴など）は強い【行動】の証拠になる。まず記録を見る。部下に聞くときは、上司が聞くと本音が出にくいので、別の人に聞いてもらうか、意見ではなく事実（最後に起きたこと）だけを聞く。
- 人数の目安：対象ユーザーに当てはまる人に **5人以上**（社内向けなら実際の利用者3人以上）。
- 聞くのは **過去の具体的な出来事** と **今やっていること**。アイデアは最後まで話さない。
- 会話の終わりに、次の一歩（コミット）を求める：次の打ち合わせ、同じ悩みを持つ人の紹介、試作品のテスト参加の約束など。

### ゲート（後半）
- [ ] 5人以上（社内は3人以上）の記録が `docs/bocchi/fieldwork/` にある
- [ ] 課題が【行動】レベルで確認できた人が過半数いる。いなければ、コンセプトを直すか、撤退基準に照らして判断した
- [ ] 【コミット】を1件以上得た（社外向け。社内の新規事業なら、承認者が時間を割いた・次の報告の場を設けた、も数えてよい）
- [ ] 本人が記録を読んで、コンセプトを更新した（更新しない場合はその理由を記録した）

### 宿題の結果を受けたときの問い詰め在庫
- **意見と行動の区別**：「その人が『欲しい』と言ったのですか、それとも実際に困って何かしていたのですか」
- **予想外**：「聞いてみて、予想と違ったことは何ですか」。何も違わなければ、聞き方が誘導的だった可能性を指摘する。
- **対象の見直し**：一番強く困っていた人に共通点はあるか。本当の対象はその人たちかもしれない。

## よくある失敗
- 解決策から話し始める／対象が「みんな」／既存AIでできることを作る／お金を払っていない領域を狙う
- 友人知人だけに聞いて「みんな欲しいと言っていた」で進む（褒め言葉は無料で、検証にならない）
