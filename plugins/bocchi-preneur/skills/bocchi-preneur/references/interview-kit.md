# 現場の宿題キット（課題インタビュー）

顧客インタビューの定番の原則にもとづく。相手が気をつかって嘘をつけないような聞き方をする。

## 3つのルール
1. 自分のアイデアではなく、相手の生活・仕事について話す
2. 将来の仮定（「使いますか？」）ではなく、過去の具体的な出来事を聞く
3. 話すより聞く

## AIが作るもの
1. **質問台本**（10分で終わる量）を `docs/bocchi/fieldwork/script.md` に作る。本人のコンセプトに合わせ、次の型で組み立てる。
   - 「最後に＿＿で困ったのはいつですか。そのとき何が起きましたか」
   - 「そのとき、どうやって対処しましたか」
   - 「それに、どれくらいの時間やお金を使っていますか」
   - 「ほかに何か試したことはありますか。なぜやめたのですか」
   - 「一番面倒なのはどの部分ですか」
   - 締め：「同じことで困っていそうな人を紹介してもらえますか」「試作品ができたら、30分触ってもらえますか」
2. **やってはいけない質問の一覧**：「このアイデアどう思いますか」「こういうのがあったら使いますか」「いくらなら払いますか」
3. **記録シート** `docs/bocchi/fieldwork/interview-NN.md`：相手の属性、聞いた事実（【行動】）、言ったこと（【発言】）、得たコミット、驚いたこと。

## 本人への渡し方
- 台本は印刷やスマホで見られる短さにする。
- 「相手の言葉をそのままメモしてください。要約はあとで一緒にやります」と伝える。
- 録音してよいかは相手に必ず確認するよう伝える。
- 報告はメモの貼り付けでよい。AIが記録シートに整理し、証拠ラベルを付ける。ラベルの最終確認は本人がする。

## 誰に聞くか
- 対象ユーザーに当てはまる人。友人・家族・社員だけにならないよう注意する（なる場合はそう記録する）。
- 外販で知り合いがいなければ、対象者が集まる場所（業界団体、コミュニティ、SNS、Reddit など）で「課題について教えてほしい」と頼む。売り込まない。

## アンケートの使いどころ
アンケートは、話を聞く相手を探す（「最近◯◯で困った人」を見つける）ためと、量の把握のために使う。検証の主役にはしない。「使いますか」「いくら払いますか」のような仮定の質問は入れない。回答者の中から、インタビューに応じてくれる人を募る。

## コミットの強さ
弱い順に：メールアドレスの登録 → 面談への参加・試作品テストへの参加 → 知人の紹介・公の推薦 → 事前予約・先行課金。
メール登録だけで検証済みとはしない。

## 海外の相手に聞く場合
台本は対象言語で作り、本人用に日本語訳を併記する。返ってきたメモはAIが翻訳して記録シートに整理し、原文も残す。

## AIによる想定インタビュー
AIが顧客役（社内の新規事業なら承認者役も）を演じる「想定インタビュー」の扱い。課題インタビュー、価値検証の面談、承認者への聞き取りのどれにも当てはまる。

### 1回目は断る
本物に聞く代わりに想定で済ませたいと最初に言われたら、断る。理由を1行で伝え、追加の問いはしない。
「想定の顧客は、あなたの頭の中の顧客です。予想と違うことを言ってくれないので、確かめたことになりません。」

### 2回目に頼まれたら作る
1. 想定インタビューを作る。記録は `docs/bocchi/fieldwork/rehearsal/` に分け、本物の記録と混ぜない。結果はすべて【推測】とし、ゲートの人数には数えない。冒頭に「想定（AIが演じた）。本物の記録ではない」と書く。
2. 作った直後に、外に出る約束を本人に決めてもらう（自由記述なので1問ずつ）。
   - 「本物に聞く1人目は誰ですか。名前か役職で教えてください。」
   - 「いつまでに聞きますか。日付で教えてください。」
   相手が思いつかなければ、この型の「誰に聞くか」の候補の場所を示す。
3. 次の4か所に、宿題が残っていることを記録する。
   - `docs/bocchi/state.md` の「出している宿題」：状態「未着手（想定で代用中）」、相手、期限
   - 意思決定ログ（`docs/bocchi/decisions/`）：「本物に聞かずに想定で進む」。本人の理由、本物に聞く相手と期限
   - Git のコミット：想定の記録と上の2つをAIがコミットし、メッセージの1行目に「宿題：未着手（想定で代用）」と入れる。push はしない
   - `docs/bocchi/report.md` の「推測のまま進んでいること」：想定で進んでいる宿題と、本物に聞く期限
4. 本物に聞けたら、状態を報告済みにし、意思決定ログの末尾に「→ 本物に聞いた（日付、人数）」と足す。想定の記録は消さず、本物の結果と食い違ったところを本人に1つ挙げてもらう。

### 想定のままでは進めないところ
SKILL.md ルール14のとおり、本物の結果が要るステップ（5・7）には、想定のままでは入れない。想定を作るときに、そのことを1行で伝える。
