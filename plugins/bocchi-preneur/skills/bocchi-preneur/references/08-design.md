# ステップ8 デザイン 🟡

## 前提
動くプロダクト（ステップ4以降）と `docs/bocchi/01-concept.md` の対象ユーザー。

## 目的
5レイヤーの最上層（表層）。「いかにもAIが作った」見た目から抜け出し、本人がこだわった見た目にする。
表層は好みだけで決めない。骨格（ステップ3）で決めた「その画面で一番大事な情報」が、見た目でも一番目立つようにする（UXの5レイヤー）。

## 進め方
1. **ムードボードを集めてもらう。** 冒頭の問い：「見た目の参考にしたいサイトやアプリを、3つ以上教えてください。それぞれ、どこが好きかも一言ください。」参考が1つだけだと模倣になるので、複数を求める。どこが好きかの一言は必ずもらう（AIが真似する要素を本人が選ぶことになる）。
2. **デザインシステムを先に作る。** いきなり画面を作らせない。まず色、文字、余白、ボタンなどの部品のルール（＝デザインシステム）をAIに作らせ、使い捨てHTMLの見本ページで見せる。ここで違和感を直す。ここが固まれば、以降の画面がぶれない。
3. **画面に適用する。** デザインシステムに沿って、主要画面から順に作り込む。適用したら、AIが主要画面ごとに次を確かめて本人に報告する。
   - **視線の流れ**：一番目立つ要素が、骨格で決めた「一番大事な情報」と同じか。画面を一瞬だけ見せたら、何が目に入るか
   - **読みやすさ**：文字と背景の明るさの差が十分か（本文はコントラスト比4.5:1以上を目安）。押せるものが押せると分かるか
   - **一貫性**：同じ意味のものが、どの画面でも同じ色・形・言葉になっているか
   結果は層の対応表の「表層」列に書き足す。
4. **比較は見て選ぶ。** 細かな案を比べるときは、文章で説明させずに使い捨てHTMLで並べる（使い捨てHTML）。登録画面のキャッチコピー案なども、チェックを入れたものだけ採用する選択ページにするとよい。

## 注意
- 既存の有名サービスのロゴ、キャラクター、固有のデザインをそのまま再現しない。参考は「好きな要素」の抽出にとどめる。
- 品質基準は「FWA、Webby Awards、Awwwards を取れる水準」のように具体的に課す。

## 問い詰め在庫
- **好きな理由**：「このサイトのどこが好きですか。色ですか、余白ですか、動きですか」
- **対象ユーザーとの一致**：「あの1人（ステップ1の対象者）は、この雰囲気を見て自分向けだと感じますか」
- **選んだ理由**：案を選んだら毎回「なぜこっちか」を一言もらう。
- **骨格との一致**：「この画面を一瞬見て、最初に目に入るのは何ですか。それは骨格で決めた一番大事な情報ですか」
- **層の取り違え**：見た目の相談に見えて、実は置き場所（骨格）や機能（要件）の変更になっていないか。そうなら、その層に戻る

## ゲート条件
- [ ] ムードボード（3つ以上、好きな理由つき）が記録されている
- [ ] デザインシステムを本人が承認した
- [ ] 主要画面にデザインシステムが適用され、本人が承認した
- [ ] 主要画面ごとに、一番目立つ要素が骨格の「一番大事な情報」と一致している（一致させない場合は理由を記録した）
- [ ] 層の対応表の「表層」列が埋まっている
