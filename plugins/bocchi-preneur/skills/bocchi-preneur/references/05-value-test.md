# ステップ5 価値検証（行動とコミットで判定）🔴＋現場の宿題

## 前提
動く試作品（ステップ4）と、`docs/bocchi/01-concept.md` の撤退基準。撤退基準がなければ、ここで先に決めてもらう。

## 考え方：意見より行動、行動よりコミット
「いいね」「使いたい」は無料で言える。プロの基準では、相手が何かを差し出したかで判定する。強い順に：
1. **お金**：事前予約、先行課金、有料ベータへの申し込み
2. **評判**：上司や同僚への紹介、公の場での推薦
3. **時間**：毎日・毎週使い続けている、フィードバック面談に来た

## 測る3つの指標（本人が選ぶ。最低2つ）
- **継続利用**：試作品を渡した人のうち、◯日後もまだ使っている人の割合
- **PMFサーベイ（なくなったら残念か）**：「このサービスが使えなくなったらどう感じますか」に「非常に残念」が40%以上を目安とする。より厳しく「過半数」を基準にする考え方もある。回答者が少ないと参考程度にしかならない。
- **お金のコミット**（外販は強く推奨）：事前予約や先行課金のページを作り、何人がお金を払ったか、またはカード登録まで進んだか。価格はこの時点の仮の値でよい（ステップ6で見直す）。実際のお金を受け取るので、受け取る前に最低限の公開準備を前倒しで済ませる：返金方針、特定商取引法に基づく表記（日本で有料販売する場合）、プライバシーポリシー。ステップ9のB（公開準備）を先に読み、本人に内容を確認してもらう。

社内ツールの場合：お金の代わりに「現場の利用者が、旧いやり方に戻らずに使い続けたか」と「上長が正式導入を承認したか」で判定する。

## 着手前に本人に決めてもらうこと（結果を見る前に）
冒頭の問い：「何人に、何日間使ってもらったら判断していいと思いますか。」
- 人数、期間、どの指標を使うか、合格基準を、結果を見る前に記録する。
- 結果を見たあとで基準を動かすのは禁止。動かしたくなったら、その理由とともに「基準変更」として記録し、変更前の基準での判定も残す。
- 対象者がステップ1の対象ユーザーと一致しているか確かめる。友人知人やフォロワーばかりなら、その偏りを記録する。
- **利用者どうしの関わりが価値になるプロダクトなら、密度を作る方法も先に決める。** 人数が判定に足りても、同じ時間に人がいなければ価値は感じられない。`docs/bocchi/02-spec.md` の最小の密度に届かせる方法を、AIが案を示して本人が選ぶ。
  - 時間を寄せる（毎晩21〜24時を「集まる時間」として案内する、など）
  - 小さな集団に絞る（同じ会社・同じ勉強会の人だけで始める）
  - 運営者自身や招いた経験者が、決めた時間に必ずいる
  - 期間中の密度（同時にいた人数）も記録し、届かなかった日は判定から分けて見る

## AIがやること
- 継続利用を測る仕組み（最低限のログ）
- PMFサーベイのアンケート文面と集計
- 事前予約・先行課金ページ（外販）
- フィードバック面談の質問台本（インタビューの型で、試作品の使い方の事実を聞く）

## 結果が出たあとの問い詰め在庫
- AIが集計・整理した結果は、本人に読み方を自分の言葉で言ってもらってから判断に進む（SKILL.md ルール11）。AIの整理を本人の判断として記録しない。
- **解釈は本人**：「この結果を見て、進みますか、作り直しますか、やめますか」。AIは結論を出さない。
- **撤退基準との照合**：「ステップ1で決めた撤退基準と照らすと、どうですか」
- **都合のいい読み**：基準未達なのに進むなら、「何を根拠に進みますか」。根拠があれば進んでよい。本人の言葉で記録する。
- **誰が非常に残念と言ったか**：その人たちに共通点はあるか。本当の対象はその人たちかもしれない。
- **自分は使ったか**：本人は試作品を毎日使ったか。

## 判断のあと（進む・作り直す・やめる のどれでも）
- **学び3行**（SKILL.md「やめると決めたら」1）を本人の言葉で書いてもらう。AIが分かったことを言うだけで済ませない。
- **意思決定ログに残す**（SKILL.md ルール12）。撤退基準に当たったのに進む・作り直すなら、そう書く。
- **作り直すなら**、さらに次の3つを本人に決めてもらう。
  - 戻り先：何を変えるかで決まる。対象や課題が揺らいだなら調査、入れるものを変えるなら企画、画面や流れを変えるなら試作。AIは候補と理由を示し、本人が選ぶ
  - 2回目の合格基準：結果を見る前に。1回目と同じ指標で比べられるようにする
  - 新しい撤退基準：全体をやめる期限と条件、作り直しを何回までするか。「2回目に届かなければ軸を移す」だけで終わらせず、どこまで届かなければやめるかまで決める
  - 戻ったら、戻り先から先のステップを「やり直し」にし、変えたことを下の層の成果物にも反映して、各ゲートと工程ゲートを確かめ直す（SKILL.md ルール8）
