# 意思決定ログ

本人が引き受けた判断を、あとから本人と読み手（事業責任者など）が読める形で残す。成果物より、このログのほうが「任せられるか」の証拠になる。外れた判断も消さずに残す。外れたときにどう戻ったかが、一番の実力の証拠になる。

## いつ書くか

次のどれかが起きたら、そのターンのうちに1件書く。迷ったら書く。

1. **工程の判断**：工程ゲートを通るとき（`phase-gates.md`）。state.md の「工程の判断」の表には1行だけ書き、詳しくはこのログに書く
2. **対象・課題・払う人・外販か社内かが変わったとき**
3. **入れる・入れないを決めたとき**（要件で「今回は入れない」と決めたもの、試作中に足した・外したもの）
4. **技術や作り方を選んだとき**（試作をアーティファクトにするかWebアプリにするか、など）
5. **ゲートを満たさずに先へ進むと決めたとき**：ステップのスキップ、宿題待ちのまま進む、説明待ちのまま進む、弱いと承知で残す
6. **基準を変えたとき**：撤退基準、合格基準（変更前の基準での判定も書く）
7. **進む・作り直す・やめる**

選択肢から選ぶだけの小さな問い（画面の並び順など）は、各ステップの成果物に書けば足りる。

## 書き方

置き場所：`docs/solo/decisions/NN-<短い名前>.md`（NN は通し番号）。雛形は `templates/decision.md`。

| 項目 | 書くこと |
|---|---|
| 問い | 何を決める必要があったか |
| 選択肢 | 2つ以上。AIが出した案には「（AI案）」と付ける。それぞれの良い点と懸念 |
| 決定 | 選んだもの |
| 本人の理由 | **本人の言葉で「」に入れる。** 「4-b」「①A」のような記号だけでは書かない。選択肢から選んだときは、選んだ理由を一言もらう |
| 根拠と証拠ラベル | 推測／発言／行動／コミット。推測のまま決めたなら、そう書く |
| 見直す条件 | どんな事実が出たら決め直すか。「あとで考える」ではなく、観察できる事実の形で（例：「インタビュー5人中3人が◯◯と答えたら」） |
| 影響 | 直したファイル、聞き直した前提 |

- AIが要約した文には「要約：」と付ける。本人の言葉と混ぜない。
- 書いたら本人に見せ、本人の理由と見直す条件が本人の考えと合っているかを確かめてもらう。直したいと言われたら直す。
- 決め直したときは、元のログを消さない。新しいログを書き、元のログの末尾に「→ NN で決め直した」と足す。

## state.md との関係
state.md の「本人が下した重要な判断」は、ログの一覧（日付・1行・ファイル名）にする。中身はログに書く。
