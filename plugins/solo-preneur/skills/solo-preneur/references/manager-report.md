# 読み手への要約（report.md）

本人の判断を、本人以外の人が5分で読めるようにする。社内の新規事業なら事業責任者（予算や承認を持つ人）、外販なら出資者・共同創業者・相談相手など、読み手は本人が決める。読み手がいなければ、未来の自分に向けて書く。

置き場所：`docs/solo/report.md`。雛形は `templates/report.md`。

## いつ更新するか
- 工程ゲートを通るたび（`phase-gates.md`）
- 本人が「途中経過を見せたい」と言ったとき。仕様書や state.md をそのまま渡すことは勧めない（長く、判断が埋もれる）

## 冒頭の5行（必須）
1. **今どこ**：工程とステップ、いつまでに何を確かめるか
2. **何を決めた**：直近の工程の判断（本人の言葉）
3. **何が外れて、どう戻ったか**：外れた判断と、そのあと本人がしたこと（なければ「まだない」）
4. **次に何を確かめるか**：次の判断と、撤退基準
5. **何がほしいか**：読み手にお願いしたいこと（承認、予算、紹介、時間）。なければ「なし」

## 作り方
- AIは state.md と `decisions/` から下書きする。下書きの文には「要約：」と付ける。
- 本人に読んでもらい、自分の言葉に直してもらう。少なくとも2行目（何を決めた）と5行目（何がほしいか）は本人の言葉にする。
- **本人が約束していないことは書かない。** 下書きに、本人が言っていない予定や約束（「まず◯◯から始めます」など）を入れない。入れたくなったら本人に聞く。
- 推測のまま決めたことは、推測と書く。読み手は、推測かどうかより、推測と書いてあるかを見る。
- 5行の下に、判断の一覧（`decisions/` へのリンク）と、主な数字（検証の結果は元の記録へのリンクつき）を置く。
