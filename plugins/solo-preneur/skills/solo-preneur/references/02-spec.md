# ステップ2 仕様設計（UXの5レイヤー下3層＋データの重さ）

## 前提
`01-concept.md` の「対象ユーザー」「課題」「最初の一段」。なければ、この3つを3問で埋めてから始める。

## 前提知識：UXの5レイヤー
UXデザインで広く使われる、ユーザー体験を5つの層に分ける考え方。下から 戦略 → 要件 → 構造 → 骨格（ステップ3）→ 表層（ステップ8）。上の層は下の層と矛盾してはいけない。このステップでは下3層を1層ずつ固める。

## 層ごとの役割分担
- 戦略 🔴：本人の言葉で埋める
- 要件 🔴：入れる・入れないは本人が決める。AIは漏れと矛盾を指摘する
- 構造 🟡：AIが利用の流れを整形し、本人が「その人は本当にこの順で使うか」を確かめる
- **データの重さ 🔴**：何を預かるかは本人が決める。AIは重さの分類と、それに伴う義務を平易に示す

## データの重さ（必ずここで決める）
扱うデータを3段階に分類し、本人に確認する。
- 軽：メールアドレス、表示名、利用ログ
- 中：氏名・住所・電話、決済情報（決済代行に任せ、自分では持たない設計が原則）、業務データ
- 重：マイナンバー、健康・医療、財務の詳細、子どもの情報、位置情報の履歴

「重」を扱う場合は、本当に最初の版で必要かを問い詰める。必要なら、ステップ9の対策と法務確認を前倒しにすることを state.md に記録する。法令上の扱いはAIが断定せず、専門家への確認を勧める。

## AI原価の上限
裏でAIが動くなら、1ユーザーあたりの利用上限（回数・量）をここで仮決めする。上限がないと、少数のヘビーユーザーで赤字になる。数字は本人が決め、ステップ7で見直す。

## ゲート
- [ ] 戦略：ターゲット、ニーズ、提供価値、事業としての目的が本人の言葉で書かれている
- [ ] 要件：優先度順の機能と「今回は入れない」もの。各要件が戦略のどれに対応するか言える
- [ ] 構造：初回利用から「価値を感じる瞬間」までの流れが1本以上ある
- [ ] データの重さが分類され、本人が確認した
- [ ] AIを使うなら、1ユーザーあたりの利用上限の仮決めがある

## 冒頭の問い
「ユーザーがこのプロダクトを使い終わったとき、何が変わっていてほしいですか。」

## 問い詰め在庫
- **目的とニーズの区別**：「それはユーザーの望みですか、あなたの事業の望みですか」
- **入れない機能**：「今回あえて入れない機能を3つ挙げてください」
- **戦略との対応**：要件ごとに「これは戦略のどの部分のためですか」
- **価値を感じる瞬間**：「初めて『これいい』と思うのは、使い始めて何分後、どの操作の後ですか」
- **データの必要性**：「そのデータがないと、最初の版は成り立ちませんか」
- **課題検証との照合**：インタビューで出た【行動】と、この流れは合っているか
