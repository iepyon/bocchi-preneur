# ステップ6 価格設計 🔴

## 前提
`05-value-test.md`（仮の価格で何人が払ったか、払わなかったか）と、`02-spec.md` のAI利用上限。なければ、仮の価格と利用上限を本人に聞いてから始める。

## 考え方
- AIが裏で動くサービスは、広告モデルでは成り立ちにくい。基本は課金。
- 「最初からお金をもらう」がプロの基準。無料ユーザーを集めてから課金を考えると、払う人がいないことに後から気づく。
- 価格は一度決めたら終わりではない。上げることもできる。最初の価格で悩みすぎない。

## 役割分担
- AI：原価の試算、利用者分布にもとづくシミュレーション、プラン案、アンケートの集計、競合の価格調査
- 本人：前提の数字、目標利益率、最終価格

## 進め方
1. 冒頭の問い：「このサービスで、利益率は最低何%は確保したいですか。」
2. **利用者分布**：ライト・ミドル・ヘビーが 2:6:2 程度という経験則を出発点にしてよい。ステップ5の利用データがあればそちらを優先する。
3. **AIが試算する**：1人あたりのAI原価（利用量別）、決済手数料、インフラ費用を置き、プラン案ごとの売上・原価・利益率を表にする。前提はすべて明記し、推測の前提には【推測】を付ける。
4. **競合と代替手段**：対象ユーザーが今払っている金額（ステップ1で聞いたもの）と、競合の価格をAIが調べて並べる。
5. **ユーザーの感覚で確かめる**：価格感度分析（PSM）の4問をベータユーザーに聞く（安すぎて不安な価格／お買い得な価格／高いが検討する価格／高すぎて買わない価格）。分布が交わる範囲が目安。ただしPSMは「意見」であり、ステップ5の実際の支払い（コミット）のほうが強い証拠だと伝える。
6. **本人が決める**。

## 海外市場の場合
- 通貨（USDなど）と、税込み・税抜きの表示を決める。
- 国ごとの価格差を付けるかを本人に決めてもらう。
- 消費税・付加価値税の扱いは、決済代行の機能（自動計算など）と税理士への確認を勧める。AIは断定しない。

## 社内ツールの場合（価格の代わり）
- 導入効果の試算：削減できる時間 × 人数 × 時給、ミスの削減などをAIが試算し、前提を本人が決める。
- 運用コスト：AI利用料、インフラ費用の月額見込み。
- 誰の承認が要るか、承認者に何を見せれば通るかを本人に聞く。

## 問い詰め在庫
- **払っている金額との照合**：「対象ユーザーは今この課題に◯◯円払っていました。この価格はそれと比べてどうですか」
- **ヘビーユーザーの赤字**：「上限を設けますか、上位プランを作りますか、受け入れますか」
- **自信**：「作り手として、この価格を自信を持って言えますか。何が引っかかっていますか」
- **無料プラン**：「無料ユーザー1人あたりの原価を、誰の売上で賄いますか」
- **安くしすぎ**：ステップ5で払った人がいるのに、それより下げようとしていたら理由を聞く。

## ゲート
- [ ] 目標利益率と前提の数字を本人が決めた
- [ ] プラン別の試算表がある（前提つき）
- [ ] ステップ5の支払い実績、またはPSMの結果、またはその両方がある（ない場合は理由を記録）
- [ ] 最終価格と理由が本人の言葉で記録されている
- [ ] 説明チェックが済んでいる（対象と記録の形は `explain-check.md`）
