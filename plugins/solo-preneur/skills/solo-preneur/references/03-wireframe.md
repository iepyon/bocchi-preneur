# ステップ3 画面設計（ワイヤーフレーム）🟡

## 前提
`02-spec.md` の利用の流れと層の対応表。なければ、主要な流れ1本を本人に口頭で説明してもらい、AIが整形して確認してから始める。

## 目的
5レイヤーの4層目（骨格）。色や装飾はまだ考えない。骨格では次の3つを決める（`references/ux-layers.md`）。
- **画面の部品配置**：入力欄・ボタン・一覧などをどこに置くか
- **移動の仕方**：画面から画面へどう移るか。今どこにいるかがどう分かるか
- **情報の見せ方**：その画面で一番大事な情報は何か。2番目、3番目は何か（優先順位）

普段の状態だけでなく、**初回（まだ何もない）・空・失敗・読み込み中**の状態も、主要画面ごとに描く。ステップ2の「操作の設計」で決めたふるまいが、ここで画面になる。

## 進め方
1. ステップ2の利用の流れから、主要な画面を洗い出し、本人に「この画面リストで漏れはないか」を確認する。
2. 主要な画面ごとに、ワイヤーフレームを2〜3パターン作り、使い捨てHTMLで並べて見せる（`references/disposable-html.md`）。
3. 選択はAskUserQuestionツールが使えれば選択肢で聞く。本人に選んでもらい、「なぜそれを選んだか」を一言もらって記録する。
4. 選んだ案の部品を、層の対応表の「骨格」列に書き足す。どの要件にもつながらない部品があれば、外すかを本人に聞く。描きながら機能を足したくなったら、画面より先に要件と対応表を直す（`ux-layers.md`「層をまたぐときのルール」）。
5. 品質の基準は言葉で曖昧にしない。「かっこよく」ではなく「FWA、Webby Awards、Awwwards を取れる水準になるまで自分で見直して」のように、具体的な到達点をAI自身に課す。

## ゲート条件
- [ ] 主要画面のリストを本人が確認した
- [ ] 各主要画面のパターンを本人が選び、理由が記録されている
- [ ] 選んだ画面の並びで、ステップ2の利用の流れが最後までたどれる
- [ ] 主要画面ごとに「一番大事な情報」が1つ決まっている
- [ ] 主要画面の初回・空・失敗の状態がある
- [ ] 層の対応表の「骨格」列が埋まり、どの要件にもつながらない部品がない
- [ ] 本人が、AIが作った骨格の要点と弱点を自分の言葉で説明し、成果物の「本人の説明」に記録されている（`explain-check.md`）

## 問い詰め在庫
- **選んだ理由**：「なぜこっちですか」。「なんとなく」なら、ユーザーの立場で使ったときを想像してもらう。
- **ユーザー視点**：「あの1人（ステップ1の対象者）が初めてこの画面を開いたら、最初にどこを押しますか」
- **削れるもの**：「この画面から1つ消すとしたら何ですか」
- **一番大事な情報**：「この画面で、あの1人に最初に見てほしいものは1つだけ挙げるなら何ですか」
- **迷子**：「この画面にいるとき、その人は自分がどこにいて、どう戻ればいいか分かりますか」
- **空の画面**：「初めて開いて、まだ何もないとき、その人には何が見えますか。そこで次に何をすればいいか分かりますか」

## 成果物 `docs/solo/03-wireframe.md`
画面リスト、移動の地図、各画面で選んだ案（ファイルへのリンク）と一番大事な情報、初回・空・失敗の状態、選んだ理由（本人の言葉）。層の対応表の更新は `02-spec.md` に書く。
