# 基準の考え方と対応表

本人に「なぜそうするのか」と聞かれたときに、このファイルを読んで答える。考え方を平易に説明する。

## 米国の独立開発・ブートストラップで定番の考え方
| 考え方 | 反映先 |
|---|---|
| 顧客インタビューでは、アイデアではなく相手の生活を、将来の仮定ではなく過去の具体を聞く。話すより聞く。褒め言葉は検証にならず、時間・評判・お金というコミットで判定する | ステップ1の課題検証、`interview-kit.md`、証拠ラベル、ステップ5 |
| 最初から大きなSaaSに賭けず、小さな製品から段階的に大きくする（階段型）。ニッチは大手には小さすぎるから勝てる | ステップ1の「大きさの問い」、ステップ11の次の一段 |
| アイデア → 作る → ローンチ → 育てる → 課金 → 自動化 → 売却、の流れ。最初から課金する、早くローンチしてユーザーと一緒に作る、人を雇う前に自動化する、多くのアイデアはやめる前提 | ステップ5のお金のコミット、ステップ7、ステップ10、ステップ11 |
| PMFサーベイ：「使えなくなったら非常に残念」が40%以上を目安とする | ステップ5 |
| 価格感度分析（PSM）：4問で受け入れられやすい価格帯を探る | ステップ7 |
| UXの5レイヤー：ユーザー体験を5層に分け、下から積み上げる | ステップ2・3・8 |

## 中国の独立開発（海外市場への展開・一人公司）で定番の考え方
| 考え方 | 反映先 |
|---|---|
| 作り手の顔を出し、公開しながら作ることで、匿名のプロダクトより早く信頼を得る | 届けるトラック 1・2 |
| 本体の手前に小さな無料ツールを作り、検索やSNSからの入り口にする（側面の入り口） | 届けるトラック 3 |
| 集めた注意はメールリストなど自分の手元に貯める | 届けるトラック、ステップ10 |
| 大手と同じ土俵で戦わず、小さな痛みを解く小さく美しいツールを作る | ステップ1 |
| 海外市場では、言語、決済、価格の通貨、法令を最初に決める | 開始時の分岐、ステップ7・9・10 |
| 現実的な期待値：時間をかけても収入が小さいケースは多い。作り手の信頼は、プロダクトが失敗しても残る | 撤退基準、ステップ11 |

## 骨格として残しているもの
コンセプト → 仕様（5レイヤー）→ 画面 → 試作（Web先行）→ 価値検証 → 本番（作るAIと確かめるAIの分業）→ 価格（利用者分布にもとづく試算）→ デザイン（ムードボード→デザインシステム→使い捨てHTML）→ ペネトレーションテスト → 素材 → 計測、の流れと、「決めるのは人」という考え方。
