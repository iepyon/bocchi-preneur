# ステップ9 セキュリティと公開準備 🟢（攻撃と修正）／🔴（リスク受容と規約の内容）

## 前提
動くプロダクトと、`02-spec.md` のデータの重さ。なければ、データの重さを先に決める（飛ばせない最小限）。

## A. セキュリティ（ペネトレーションテスト）
1. **範囲を本人に確認する。** 攻撃してよいのは、本人が所有・管理する自分のアプリのローカル環境・テスト環境だけ。本番の実ユーザーデータ、外部サービスそのものは対象外。
2. **`pentester` エージェントに攻撃させる。**（＝攻撃者役になって実際に侵入を試すテスト）
3. **突破された所をすべて直し、同じ攻撃で再確認する。**
4. **残ったリスクは本人が判断する**：公開前に直す／公開後に直す／受け入れる。
5. **秘密情報**（APIキー、パスワード）がコードやGitに含まれていないかを必ず確認する。
6. データの重さが「重」なら、セキュリティに詳しい人間のレビューを受けることを強く勧める。

## B. 公開準備（外販は必須）
AIは下書きを作れるが、**法的な助言はできない**。本人の事業内容に合っているかを本人が確認し、課金や重いデータを扱うなら専門家（弁護士・行政書士など）の確認を勧める。

- **利用規約**：禁止事項、免責、AIの出力の扱い、解約・返金の条件
- **プライバシーポリシー**：何のデータを、何のために、どこに（AI事業者への送信を含む）、どれくらい保存するか
- **特定商取引法に基づく表記**（日本で有料で売る場合）：事業者名、連絡先、価格、支払い時期・方法、返品・解約の条件など
- **海外に売る場合**：GDPR（欧州）など、売る地域のルールがあることを伝え、専門家への確認を勧める
- **サポートの窓口**：問い合わせ先、返信の目安
- **返金・解約の流れ**：ユーザーが自分で解約できること

社内ツールの場合：社内の情報セキュリティ規程、扱うデータの持ち出し可否、承認フローを本人に確認する。

## ゲート

- [ ] ペネトレーションテストを実施し、「致命的」「重大」が修正・再確認済み、または本人が理由つきで受け入れた
- [ ] 秘密情報がコードやGitにない
- [ ] 外販：利用規約、プライバシーポリシー、（有料なら）特商法表記、サポート窓口、解約の流れがそろい、本人が内容を確認した
- [ ] 社内：社内規程との適合を本人が確認した
